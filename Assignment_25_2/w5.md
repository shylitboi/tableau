# 학습 내용 정리

## 39강. LOD

<!-- INCLUDE, EXCLUDE, FIXED 등 본 강의에서 알게 된 LOD 표현식에 대해 알게 된 점을 적어주세요. -->

**LOD (Level of Detail)** 식은 시각화에 표시된 차원과는 독립적으로, 사용자가 원하는 **집계 수준(Level of Detail)** 을 직접 제어할 수 있는 계산식이다.
즉, 뷰의 세부 수준과 무관하게 특정 차원을 기준으로 한 집계가 가능하다.

예시:

* **FIXED**: 지정한 차원에 고정된 수준으로 계산
* **INCLUDE**: 현재 뷰의 차원에 추가적으로 특정 차원을 포함해 계산
* **EXCLUDE**: 현재 뷰의 차원 중 일부를 제외하여 계산

이러한 LOD 표현식을 통해 시각화의 뷰 구조와 관계없이 **정교하고 일관된 분석 지표를 정의**할 수 있다.


## 40. LOD EXCLUDE

<!-- INCLUDE, EXCLUDE, FIXED 등 본 강의에서 알게 된 LOD 표현식에 대해 알게 된 점을 적고, 아래 두 질문에 답해보세요 :) -->

> **🧞‍♀️ FIXED와 EXCLUDE를 사용하는 경우의 차이는 무엇인가요?**

```
FIXED: 뷰에 표시된 차원과 관계없이 '지정된 차원' 기준으로 계산을 고정함.  
EXCLUDE: 현재 뷰의 차원 중 일부를 제외하여 상위 수준의 집계를 수행함.

- FIXED → 뷰에 영향을 받지 않는 독립적 계산 (차원을 고정)
- EXCLUDE → 뷰의 일부 차원을 제거하여 더 높은 수준에서 계산

예)
{ FIXED [Region] : SUM([Sales]) } → 지역별 총매출을 고정 계산  
{ EXCLUDE [Category] : AVG([Sales]) } → 카테고리를 제외한 평균 매출 계산
```

> **🧞‍♀️ ATTR 함수를 사용하는 이유는 무엇인가요?**

```
LOD 계산식은 세부 수준이 달라 여러 행(row)을 반환할 수 있으나,
시각화에서는 단일 값만 표현되어야 함.  
이때 ATTR 함수는 여러 값 중 유일한 하나의 값을 반환할 때 해당 값을 보여주는 역할을 한다.  
즉, 다수의 행 중 대표값이 존재할 때 이를 안전하게 표현하기 위해 사용함.
```



## 41. LOD INCLUDE

<!-- INCLUDE, EXCLUDE, FIXED 등 본 강의에서 알게 된 LOD 표현식에 대해 알게 된 점을 적고, 아래 두 질문에 답해보세요 :) -->


1. FIXED: 시각화의 차원과 관계없이 일정 기준으로 계산할 때 사용
   예) { FIXED [Customer ID] : SUM([Sales]) }
       → 고객별 매출 합계를 고정적으로 계산

2. INCLUDE: 뷰의 세부 수준보다 더 세밀하게 계산한 후, 상위 수준에서 표시할 때 사용
   예) { INCLUDE [Product Name] : AVG([Discount]) }
       → 제품별 평균 할인율을 구한 뒤, 이를 카테고리 수준에서 표시

3. EXCLUDE: 뷰의 차원 중 일부를 제거하여 상위 수준의 집계를 수행할 때 사용
   예) { EXCLUDE [Category] : SUM([Sales]) }
       → 카테고리를 무시하고 지역별 총매출 계산


LOD 표현식은 데이터의 **세부 집계 수준을 명시적으로 정의함으로써**,
뷰의 구조나 필터 조건에 의해 계산 결과가 달라지는 문제를 방지한다.




## 42. 매개변수

<!-- 매개변수에 대해 알게 된 점을 적어주세요 -->

> **🧞‍♀️ 집합에도 매개변수를 적용할 수 있나요? 시도해봅시다**

**매개변수(Parameter)** 는 사용자가 직접 값을 입력하거나 선택할 수 있는 **동적 변수**이다.
이를 활용하면 사용자의 입력에 따라 **필터링, 계산식, 또는 시각화 요소**가 실시간으로 변경되도록 구성할 수 있다.

특히 LOD나 집합(Set)과 결합하면,
“사용자 지정 기준에 따른 동적 분석(예: 특정 기간, 특정 범주의 매출 비교)”이 가능하다.

> **🧞‍♀️ 집합에도 매개변수를 적용할 수 있을까요? 직접 시도해봅시다.**
> 매개변수를 집합 조건에 연결하면 사용자가 임의로 범위를 조정하거나 기준값을 바꿔서 **대화형 분석 환경**을 구현할 수 있다.


## 43. 매개변수 실습

<!-- 영상 묶음에 포함되지 않아 찾기 어려우실까 링크를 아래에 첨부하겠습니다. 수강 후 삭제해주세요-->



차원 변경
```
CASE 함수를 이용해 매개변수 값(예: 국가, 고객, 세그먼트 등)에 따라
표시되는 차원을 전환할 수 있도록 계산 필드를 작성.
→ 뷰(View)의 행(Row)에 배치하여 실시간 차원 변경 구현.
```

측정값 변경:
```
매개변수로 매출·수익·수량 중 하나를 선택하면,
CASE 함수를 통해 해당 지표의 합계를 계산하고 그래프가 자동으로 갱신되도록 설정.
→ 시트 제목에 매개변수를 삽입해 선택된 지표를 표시.
```

핵심 포인트:
```
매개변수는 단독으로는 작동하지 않으며, 반드시 계산식·필터·참조선과 결합해야 한다.
이를 통해 사용자 입력에 따라 시각화의 요소를 동적으로 제어하는 인터랙티브 분석 환경을 구현할 수 있다.
```

## 45. 워크시트 마크카드

<!-- 마크카드에 대해 알게 된 점을 적어주세요 -->
**마크카드(Marks Card)** 는 시각화의 표현 방식을 정의하는 핵심 요소이다.
색상(Color), 크기(Size), 형태(Shape), 레이블(Label), 세부정보(Detail) 등 다양한 속성을 조정하여 데이터를 직관적으로 표현할 수 있다.

워크시트별 마크카드는 서로 독립적으로 적용되며, 동일한 데이터라도 **표현 방식의 차이에 따라 인사이트의 방향이 달라질 수 있다.**


## 46. 서식 계층

<!-- 서식계층에 대해 알게 된 점을 적어주세요 -->
서식 계층은 태블로에서 서식이 적용되는 **우선순위를 결정하는 구조적 개념**이다.
서식은 상위 수준에서 설정할수록 전역적으로 적용되며, 하위 수준에서 다시 세부 조정이 가능하다.

> **🧞‍♀️ 서식 계층을 일반적인 것에서 구체적인 순서로 정리해보세요.**

```
Workbook > Worksheet > Field > Row/Column > Mark
```

즉, 통합 문서 전체의 기본 서식이 가장 넓은 범위를 가지며,
세부 요소(예: 마크 단위)로 갈수록 구체적이고 제한적인 서식이 적용된다.


## 47. 워크시트 서식

<!-- 워크시트 서식에 대해 알게 된 점을 적어주세요!-->
각 워크시트에서는 색상, 선, 글꼴, 숫자 형식 등 세부 서식을 개별적으로 설정할 수 있다.
서식은 앞서 언급한 **서식 계층의 우선순위**에 따라 적용되며,
상위 수준의 서식은 하위 수준에서 **덮어쓰기(overriding)** 가능하다.

이를 통해 동일한 데이터라도 시트별 목적에 맞게 **시각적 일관성 및 가독성을 조정**할 수 있다.
